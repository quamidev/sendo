## Exporting a number’s history [#export]

How long you keep conversations, and when you hand them over or delete them, is the operator’s decision: your app’s, not Sendo’s. A clinic may be legally required to keep records for years, or to delete them within a period. Sendo gives you the two tools and never runs either on its own: disconnecting a number keeps everything (read-only), and nothing is deleted until you call `purge`.

`sendo.accounts.export(id, { actor })` returns the whole history of one number, connected or disconnected, as an `AsyncIterable<string>`: the chunks of a single JSON document. Only admins can export (`numbers.manage`): any other actor gets `ForbiddenError` (`FORBIDDEN`) when you call it, before any chunk. A number of another tenant rejects the first chunk with `AccountNotFoundError`. `id` is the account id or the phone number id.

```ts title="app/api/numbers/[id]/export/route.ts"
import { exportFileName } from "@quami/sendo";
import { sendo } from "@/lib/sendo";

export async function GET(_request: Request, { params }: { params: Promise<{ id: string }> }) {
  const { id } = await params;
  const actor = await currentActor(); // sendo.actor(userId, tenantId) for the signed-in user
  const chunks = sendo.accounts.export(id, { actor }); // ForbiddenError for non-admins
  const iterator = chunks[Symbol.asyncIterator]();
  const first = await iterator.next(); // AccountNotFoundError before any byte is sent
  const account = await sendo.accounts.get(id);
  const encoder = new TextEncoder();
  const body = new ReadableStream<Uint8Array>({
    start(controller) {
      if (!first.done) controller.enqueue(encoder.encode(first.value));
    },
    async pull(controller) {
      const next = await iterator.next();
      if (next.done) controller.close();
      else controller.enqueue(encoder.encode(next.value));
    },
  });
  return new Response(body, {
    headers: {
      "Content-Type": "application/json",
      "Content-Disposition": `attachment; filename="${exportFileName(account.displayPhone, new Date())}"`,
    },
  });
}
```

Map `ForbiddenError` to 403 and `AccountNotFoundError` to 404 before streaming.

From a terminal, `npx @quami/sendo accounts export <id> --out history.json` writes the same document ([CLI](/docs/cli#accounts-export)).

- **Streamed.** Conversations are read 200 at a time with each thread paged inside, so memory stays flat for numbers with tens of thousands of messages. Write the chunks out as they come.
- **A snapshot.** Everything with `createdAt <= exportedAt` (the moment the export started); messages and conversations written while it runs are left out.
- **Media as references, not files.** Each media item has its `storageKey` and a `url` signed for 7 days when your media store can sign; otherwise `url` is `null` and you fetch it by `storageKey`. `missing: true` means the file was never stored (download pending or failed) or the store could not sign it, for example because your own retention job already deleted it.
- **File name.** `exportFileName(displayPhone, exportedAt)` returns `sendo-export-50222345600-2026-10-12.json` (the number’s digits and the UTC date).

### Export format (v1) [#export-format]

The document is `SendoExportDocumentV1` (exported from `@quami/sendo`). Dates are ISO 8601 strings; `metadata` is the stored message metadata, so system events keep `event`, `by` and their params.

| Field                        | Notes                                                                                                                                                                                              |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `account`                    | The number as stored, `active: false` once disconnected. No token or `tokenRef`.                                                                                                                   |
| `contacts`                   | Every contact with a conversation on the number. `optIn.at` is when marketing consent was decided (`null` = never).                                                                                |
| `tags`                       | The tenant’s tag catalog; conversations point to it with `tagIds`.                                                                                                                                 |
| `conversations[].assignedTo` | The current assignee; past assignments are the `assigned` / `unassigned` system events in `messages`.                                                                                              |
| `conversations[].closedAt`   | When the last `closed` system event was written, for a closed conversation; else `null`.                                                                                                           |
| `conversations[].messages`   | Newest first (the inbox thread order): contact and outbound messages, internal notes (`internal`, sender `human`), system events (`internal`, sender `system`) and pending agent drafts (`draft`). |
| `messages[].media`           | Zero or one item: references only, never the bytes.                                                                                                                                                |

New fields may be added in a later `version: 1` export; a breaking change bumps `version`.

## Deleting a number’s history (purge) [#purge]

`sendo.accounts.purge(id)` is separate from export and only works on a **disconnected** number: it deletes the account, its contacts, conversations, messages, media rows and templates, then the media files. An active number throws `AccountStateError` (`ACCOUNT_STATE`) and nothing is deleted, so the order is always `disconnect`, export if you need a copy, then `purge`. There is no undo. Whether and when to purge is your retention policy ([Deleting an organization’s data](/docs/numbers-and-tenants#purge)).
