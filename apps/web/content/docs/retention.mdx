## sendo_events (built in) [#events]

Every webhook POST is stored raw in `sendo_events` so failed events can be reprocessed. Rows older than 30 days should be deleted. Pick one of the two options below; running both is harmless.

## Option B: Vercel Cron [#vercel-cron]

Without pg_cron, call `sendo.maintenance.prune()` from a scheduled route. It deletes events older than `eventRetentionDays` (default 30) and returns the count; pass `{ olderThanDays }` to override.

## Messages and media (your policy) [#messages-media]

Sendo never deletes `sendo_messages`, `sendo_media` or stored files. How long conversations are kept is your app’s decision (and, for health or financial data, often a legal one). A starting point that deletes files through the Storage API and then the messages (their `sendo_media` rows cascade):

<Sample file="message-retention.ts" title="app/api/cron/sendo-message-retention/route.ts" />

<Callout>

- Delete files before rows: once the `sendo_media` row is gone you lose the storage path.
- The sample handles up to 1,000 files per run; schedule it often enough or loop.
- Deleting messages also removes them from the inbox and from agent history. Archive first if you need an audit trail. See [Security](/docs/security).

</Callout>
